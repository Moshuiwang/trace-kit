> 出处：lingxi [docs/产品合同与外部边界.md](https://github.com/Moshuiwang/lingxi/blob/caa845d77fbd2d6381de304dc6047498aa84c782/docs/产品合同与外部边界.md) 的章节结构与状态口径；验证：全仓；分档 G2（骨架，内容留空）。

>
> 本文每个 `##` / `###` 章节名都必须在[产品验收矩阵第二节](技术设计/验收矩阵.md#二合同条款覆盖清单)里恰好出现一次（门禁 `scripts/ci/check_acceptance_matrix.py` 逐节核对）：新增或改名章节时同步登记。其他文档转述本文条款时只给链接和章节名；需要写成归属断言的，按 `scripts/ci/check_contract_attribution.py` 的登记制核对。

## 不提供

这里换成你的：明确不做的事。每条写成可被主动违规证伪的形态（“不得 / 一律不 / 禁止”），并在验收矩阵里配否定断言。

## 动态工作的去向

需求、缺陷、研究、待决策与实施任务写 GitHub Issue；代码改动与审查写 PR；进度看 Project 与 `docs/traces/` 三件套。本文只保留稳定规则，不记录进度。
