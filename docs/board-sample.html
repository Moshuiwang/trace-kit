Trace 看板样稿

从任务表 + GitHub 证据生成的派生视图。形状是类型，颜色是状态，列是批次；时间只在「卡住多久」上出现。左边是合成的执行中样例，右边是 Trace #1 的真实收口态。

怎么读这张图

  • 从左到右是批次推进；「现在」竖线左边全绿，右边是正在做和还没做的。
  • 红虚边是卡住：运行中却超过 90 分钟没有任何外部证据。图只看得到留痕这一半，窗口是否活着要 guardian 核。
  • 黄色是自述未证：任务表勾了，但 GitHub 上找不到独立于勾选提交的制品。这一格不阻断任何事，只是让它被看见。
  • 灰虚 + 红点回边是审核结论失效：候选 SHA 变了，旧结论作废，回边指向改动来源。
  • 粗虚线是审批边：人工闸是边上的条件，不是一个待办。
  • 每列底部是这一批费在哪：子代理人次（自述）、PR 数、门禁次数；顶部预算条对照合同上限，超线只变色不拦。

这份样稿是什么、不是什么

  • 页面里的布局逻辑（按批次分列、按前驱排序、画边）就是生成脚本要做的事；真实版本输出纯 SVG，提交进 Trace 目录，tracking Issue 里以图片引用，同一份 SVG 再包进这样一个自足 HTML。
  • 演示数据是合成的，为了把九种状态都摆出来；Trace #1 的节点、指针、预算数字来自本仓 git / gh 实测，类型是人工标的。
  • 没有交互跳转、没有实时刷新、没有服务器；这三件都不在 v0 里。
  • 没有甘特图：时间不是重点，只保留「多久没证据」。
