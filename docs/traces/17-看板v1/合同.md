## 现场事实与已知坑（编排者必读）

- 样稿 `board-tui-sample.py`（`sample/board-v0` @ 4844b5d）是视觉与交互基准，不是交付物；它的 `draw_graph` 框宽固定、同层横排，分组后每层节点数要可控。
- lingxi 临时脚本 `lingxi-archive/ux-board.py` 里已验证的数据取法可参考：`git worktree list --porcelain` 识别子代理 worktree、按改动文件映射 Step、tmux 窗口名模式 `ux-b[0-9]+`、`gh run list --workflow --branch` 计数、`docker ps` 取镜像 tag；其结构（字符串切分 exec 样稿）**不复用**。
- lingxi prod 命令只认 lingxi 合同 §2 规定的生产只读原形（不加连接参数、不套循环、不接管道前缀；具体见接手卡）；证据源配置里的命令按此形态写，分类器拦了就记「未知」。
- lingxi 任务表行格式 `- [x] S-X-N 一句话（指针）`，章节用 `##`；#606 任务表已有「块 A / Wave 0 / Wave 1 / Wave 2 / Wave 3 / 收口」六节，可直接作为模块分组样本。
- codex：`codex exec -s read-only -c model="gpt-5.6-sol" -c model_reasoning_effort="max" -`，证据内嵌 stdin、输出直写文件、PID `kill -0` 判活、挂死 `pkill -9 -f vendor/.../codex` 后原样重跑；后端 404 是瞬时故障不是账号失效。
- 时间戳现取 `TZ=Asia/Shanghai date`（本机系统时区 UTC）；trace-kit 与 lingxi 两仓 `gh` 命令都要带 `-R`。
