# 看板引擎接口约定（Trace #17；并行施工的共同基线，编排者 `hb-b1` 维护）

> 依据：[合同.md](合同.md) §1 / §3、trace-kit #12 v3（v2 十二条裁定不变）、lingxi #578 / #579 / #580 / #581 / #582 / #589 已定事项、[决策清单.md](决策清单.md) D-1 / D-2 / D-7。**改本文件先改 `plugin/scripts/boardlib/model.py`，两者同源；子代理发现约定不可行时报编排者，不自行改约定。**

## 0. 铁律

1. 只用 Python 3 标准库（3.12；`tomllib` 可用）＋ 外部命令 `gh` / `git` / `tmux`（可选 `ssh`，只经证据源配置声明）。不引入第三方运行时依赖。
2. 引擎（`plugin/`、`template/`）不含任何项目专属名词、主机名、本机路径、凭据形态——`scripts/kit/check_no_lingxi.sh` 会扫描；项目专属证据全部走 §9 证据源配置。
3. 状态只认结构化证据（§7 登记表），**不得嗅探评论措辞**；证据不可得显示「未知」，不回落到「待办」或上一级结论。
4. 每个模块只由一个子代理写；跨模块只通过 `model.py` 的类型交换数据。
5. 子进程一律 `stdin=DEVNULL`、显式超时；整轮构建有超时上限；时间显示为 UTC+8 显式换算，内部全用带时区的 UTC `datetime`。
6. 引擎对目标仓库**只读**：不得执行 `git fetch` / `pull` / `checkout` / `add` / `commit` / `stash` 等任何写操作（远端状态一律经 `gh` 取），不得在目标仓库创建文件。

## 2. CLI（`board.py`；`allow_abbrev=False`）

```
board.py --repo-root <dir> [--trace N] [--config <toml>] [--branch <name>]
         [--view simple|complex] [--dump] [--why] [--now <ISO8601>] [--width W] [--height H]
         [--interval SEC] [--timeout SEC] [--no-anim]
         [--fixture <dir>] [--record <dir>] [--registry]
```

- `--trace` 缺省＝`docs/traces/` 下编号最大的 `<n>-<短名>/`；`--branch` 缺省＝配置 `[trace].branch` → 含 `<n>` 的 PR 分支（`batch/<n>-*` 优先）→ 未知。
- `--dump`：打印一帧纯文本后退出（默认 150×52，`--width/--height` 覆盖；不读终端尺寸）；`--why` 在帧后追加证据链表（§7.6）。
- `--fixture <dir>`：从 `<dir>/任务表.md` ＋ `<dir>/snapshot.json` 回放，零网络；`now` 取 `--now`，缺省取 `snapshot.json` 的 `now`。
- `--record <dir>`：真实采集一次并写 `<dir>/snapshot.json`（供做夹具），不渲染。
- `--registry`：打印登记表 Markdown（S-6 文档同源；S-5 单测比对）。
- `--interval` 默认 300 秒（#12 裁定 1）；`--timeout` 整轮构建上限，默认 60 秒。

## 3. 数据流

```
collect.collect(repo_root, trace_no, branch, conf, now, source) -> Snapshot      # 只采集，不判断
infer.infer(snapshot, conf) -> Board                                              # 只判断，不取数据
render.dump(board, view, W, H, why) -> str ；render.frame(board, view, W, H, scroll, phase) -> (lines, anim, avail)
tui.run(args, build) ；build() -> Board（tui 在后台线程调用，超时 / 异常 → 保留上一帧＋头部告警）
```

`Board.validate()` 在 `infer` 末尾与 `render` 入口各调一次：状态串、档位、来源角标、模块索引越界一律 `ValueError`（lingxi #582「写错状态字符串即报错」）。

## 4. 数据模型

以 `model.py` 为准。要点：

- `Val(value, grade, source, at, available)`：带来源角标的取值；`available=False` 渲染为「未知」。`grade` ∈ 实测 `measured` / 自报 `reported` / 推断 `inferred`，角标字 实 / 报 / 推。
- `Status`：`todo ready running watch stalled human done doneq stale unknown`（九色＋未知）。
- `Tier`：`0 未审 / 1 / 2 / 3 / 4（3 轮以上）`，即边框档位。
- `Step` ← 任务表一行；`Section` ← `##` 章节（＝简易版模块）；`TaskTable`。
- `ProviderResult(key, ok, value, error, cmd, fetched_at, grade)`；`Snapshot(now, repo, trace_no, trace_dir, branch, tasktable, results, config)`，`to_json()` / `from_json()` 可逆。
- `StepView`、`ModuleView`（含 `Rounds` 五个 `Val`）、`Header`（含五级 `StageLevel`）、`Board`、`Why`。

## 5. 任务表语法（`tasktable.py`）

- 章节：`^## (.+)$`；章节标题去掉尾部括号说明后作模块名。`##` 之前的行不属任何模块。
- Step 行：`^- \[( |x|X)\] (S-[0-9A-Za-z-]+|W0-\d+|[A-Z]-\d+(?:-\d+)?[a-z]?)\s+(.*)$`；编号后一句话到第一个 `——` / ` — ` / `（` 之前为标题；括号 / 破折号之后为指针区。
- 行尾可选标签块 `[t:impl needs:S-1,S-2 own:x est:45m]`（四键全可选；`t:` ∈ impl review gate human deploy research contract，缺省 impl；`needs:` 缺省＝同章节上一条，章节首条＝上一章节末条；`est:` 只认 `\d+m` / `\d+h`，其他一律无预估）。
- 指针提取：`PR #(\d+)`、`#(\d+) 合[入并]`、`` `([0-9a-f]{7,40})` ``、`issuecomment-(\d+)`、URL。
- 无法解析的 `- [` 行进 `unparsed`（灰色自由文本卡片、头部计数），不报错退出；字数超限（编号 > 6 字符、标题 > 18 汉字）进 `overlong` 只计数不截断。
- Trace #1 任务表与 `plugin/templates/任务表.md` 的示例行不带标签块必须全部可解析。

## 6. 内置证据键（`collect.py`；`snapshot.json` 的 `results` 键）

| 键 | 命令（只读） | 用途 |
| --- | --- | --- |
| `git.log` | `git log <branch> --date=iso-strict --format=%H%x1f%ad%x1f%an%x1f%s`（全分支 `--all` 备用） | 含 Step ID 的提交、时间 |
| `git.tasktable_history` | `git log --reverse --format=%H%x1f%ad -- <任务表>` ＋ 逐提交 `git show <sha>:<任务表>` | 每个 Step 首次勾选时刻（推断级） |
| `git.worktrees` | `git worktree list --porcelain` ＋ 每个 worktree 的 HEAD / 分支 / `rev-list --count <branch>..HEAD` / 改动文件 / 最近提交时刻 | 运行中证据、候选 SHA 是否变化 |
| `git.tags` | `git tag --format=%(refname:short)%x1f%(creatordate:iso-strict)%x1f%(objectname)` | 本地 tag（可能滞后，只作参考） |
| `gh.tags` | `gh api repos/<repo>/tags --paginate=false`（取前 30）＋ 必要时 `gh api repos/<repo>/git/ref/tags/<tag>` | **已发布 tag 的权威来源**（引擎不 fetch，本地 tag 可能滞后） |
| `gh.prs` | `gh pr list -R <repo> --state all --search <n>` 与 `--head <branch>`：number,title,state,isDraft,createdAt,mergedAt,mergedBy,reviews,headRefName,mergeCommit,statusCheckRollup | PR 节点、合主干、自合 / 零批准 |
| `gh.issue` | `gh issue view <n> --json state,closedAt,comments`（评论只取 createdAt / author / 正文首行） | 收口、评论标题匹配、最后留痕 |
| `gh.runs` | `gh run list -R <repo> --branch <branch> --limit 100 --json name,workflowName,conclusion,status,createdAt,updatedAt,headSha,event` | CI 红绿、完整门禁 vs 文档路由计数 |
| `gh.release_runs` | `gh run list --workflow <配置的发布工作流> --branch main --limit 10 …` | 已发布 |
| `tmux.windows` | `tmux list-windows -t <配置的 session> -F '#{window_name}'` | 编排窗口存活（仅配置声明时） |
| `config.<key>` | 证据源配置声明的每条命令（§9） | 预发 / 生产 tag、预算计数、附加证据 |

每条失败（命令不存在、非零退出、超时、输出解析失败）→ `ok=False`，`error` 留原因；**不抛异常、不给默认值**。`LiveSource` 并发执行（线程池），单条超时默认 25 秒，整轮受 `--timeout`。`RecordedSource` 只读 `snapshot.json`。

## 7. 推断规则（`infer.py`）

### 7.1 步骤状态（#12 v2 第 3 条；全部机器判定）

| 状态 | 判定 | 证据类型（登记表） |
| --- | --- | --- |
| `done` 绿 | 已勾选且有独立制品（指针指向的 PR MERGED / 提交存在 / 评论存在） | checkbox ＋ pr_state / commit_time / comment_title |
| `doneq` 黄 | 已勾选但无独立制品 | checkbox |
| `human` 紫 | `t:human` 且未勾选 | tasktable_tag |
| `running` 蓝 | 未勾选、60 分钟内有证据（含 Step ID 的提交 / worktree 最近提交 / PR / CI / 评论） | commit_time / worktree / pr_state / ci_conclusion / comment_title |
| `watch` 橙 | 未勾选、最近证据 60–90 分钟前 | 同上 |
| `stalled` 红 | 未勾选、有证据但 > 90 分钟无新证据 | 同上 |
| `ready` 亮蓝 | 未勾选、无证据、依赖全 `done` | checkbox（依赖） |
| `todo` 灰 | 其余未勾选 | checkbox |
| `stale` 灰暗 | `t:review` 步骤绑定的候选 SHA（指针里的 SHA）已不是分支 HEAD 且步骤未勾选 | sha_equal |
| `unknown` | 判定所需证据键 `ok=False` | （所依赖的键） |

「有证据」的归属：提交信息 / 分支名 / worktree 目录名 / PR 标题正文 含 Step ID（词边界）；评论首行含 Step ID。

### 7.2 模块聚合（简易版节点）

- 状态优先级：`stalled > watch > running > human > unknown > ready > doneq > todo`；全部 `done` → `done`；全部 `done`/`doneq` 且含 `doneq` → `doneq`。
- 三行：①「干什么」＝章节名 ＋ `完成/总数`；②「轮了几轮」＝`审 N · 外 N · 修 N · CI 红N 绿N`（各带角标）；③「证据在哪」＝`PR #n 状态 · 评论 N · 最新 HH:MM`。标题行右侧 `实际或已跑/预估`。
- 轮数（lingxi #578 已定）：模块内评论**首行**匹配 `审核[①②③④⑤]|审[①②③④⑤]|审核\s*[1-5]\s*轮|独立审核.*结论` → 审；`外审|codex|agy` 且 `结论|账本` → 外；`修复包` → 修；归属＝首行含该模块任一 Step ID，否则记入 Trace 级（头部）。CI 红绿＝分支上落在模块活动窗口 [首证据, 末证据或 now] 内的工作流 run 结论（推断级）。
- 边框档位 `Tier` ＝ 审核轮数（审 ＋ 定向复核）：0 / 1 / 2 / 3 / >3。
- 模块依赖：有 `needs:` 跨章节标签则按标签去重，否则按章节顺序链。

### 7.3 时长（#12 v2 第 6 条；lingxi #581）

- 实际＝模块 / 步骤首个证据到最后证据（GitHub 时间戳，分钟）；运行中显示已跑＝首证据至今；无派发证据的步骤开工时刻 `?`。
- 预估＝`est:` 之和；没有标签显示 `/─`（不编数）。
- 自报数（评论里的人次等）不参与超支判断，角标「报」。

### 7.4 五级阶段（lingxi #589）

| 级 | 证据 | 取值 |
| --- | --- | --- |
| 合入主干 | 批次 PR `state == MERGED` | 是 / 否 / 未知 |
| 已发布 | 发布工作流最近 run 结论 `success` 且其 headSha 为合并提交或其后代，＋ 产出 tag（`gh.tags` 中指向该 headSha 或晚于合并时刻的 tag；`git.tags` 只作参考） | 是 / 否 / 未知 |
| 预发已升级 | 配置 `[stages.staging]` 命令取得的 tag == 已发布 tag | 是 / 否 / 未知（未配置＝未配置，不显示未知） |
| 已上生产 | 配置 `[stages.production]` 同上 | 同上 |
| 收口 | Trace Issue `state == CLOSED` | 是 / 否 / 未知 |

推断链能表达「已完成」：生产 == 已发布 → 阶段「已上生产」、下一步「观察与收口」；Issue 关闭 → 阶段「已收口」。上一级未知时本级仍按自身证据判定，不沿用旧结论。

### 7.5 头六项（#12 v2 第 10 条）

阶段（含五级一行）· 阻塞（红）· 下一步（蓝：第一个未勾选 Step ＋ 编排窗口 / worktree 数）· 预算（配置声明的计数条；无配置只显示 PR 数与 CI 次数，不画上限）· 存疑（黄：自述未证条数、合同 PR 自合 / 零批准、共用 PR）· 最后外部证据。固定附注「窗口状态未知，需元守护核」除非配置声明了窗口模式且取到值。

### 7.6 `--why` 证据链

每个 Step / 模块 / 阶段级一行：`对象 | 状态 | 证据类型 | 来源（只打印证据键，如 `config.staging`，**不打印命令原文**——命令可能含主机名，`--dump --why` 会贴到公开 Issue） | 取值 | 取值时间（UTC+8）| 可得`。命令原文只留在 `snapshot.json`（`ProviderResult.cmd`）；含项目专属命令的快照不得提交进本仓。

## 8. 渲染要求（`render.py`）

- 简易版（默认，D-7）：模块节点 5 行框（标题行 ＋ 三行 ＋ 底边）；**150×52 下 6 个模块不滚动**（允许连线带压成 1 行、独立模块并排）；复杂版＝每 Step 卡片（沿用样稿 `layout` / `draw_graph`，允许滚动）；`v` 切换，两视图同一 `Board`。
- 四档边框（D-1）：未审 `┌─┐│└┘`；1 轮 `╔═╗║╚╝`；2 轮 `┏━┓┃┗┛`；3 轮 `┏╍┓┇┗┛`；3 轮以上同 3 轮 ＋ 标题行 `⟲N` ＋ 醒目色（208）。图例行固定呈现五档样张。颜色仍表示状态（样稿 `C` 表）。
- 来源角标：数字后紧跟一字 实 / 报 / 推，用暗色（240）。「未知」用 245 色斜体不可用时用 `?`。
- 卡片文字不出现省略号（超限只在头部计数）；宽字符按东亚宽度计算（沿用样稿 `cw/dw`）。
- `dump()` 输出不含 ANSI 色（纯文本），不含 session 名与本机路径。

## 9. 证据源配置 TOML（`config.py`；S-4 定稿，草案）

```toml
[trace]            # 可选
number = 606
branch = "batch/606-xx"
[repo]             # 可选；缺省 git remote
slug = "owner/repo"
[orchestrator]     # 可选：编排窗口存活
tmux_session = "<session>"
window_pattern = "^xx-b[0-9]+$"
[release]          # 可选：发布工作流名
workflow = "Main Publish"
[stages.staging]   # 预发；[stages.production] 生产；命令只读、单条扁平、显式超时
command = "..."; parse = "regex:...(\\S+)$"; timeout = 20; grade = "measured"
[budget.full_gate] # 预算计数条；label / cap / command / parse / grade
label = "完整门禁"; cap = 5; command = "gh run list ..."; parse = "int"
[[evidence]]       # 附加证据行（头部「外部证据」）
key = "x"; label = "..."; command = "..."; parse = "lines"; timeout = 25
```

未知键 / 类型错误 → `ConfigError` 带键路径（tomllib 不给键的行号，语法错误才有行列）；每条命令 `bash -o pipefail -c`、`stdin=DEVNULL`、独立进程组、超时杀整组；输出经 `parse` 规则（缺省 `text` / `int` / `regex:<pat>` 取第一捕获组 / `lines` / `json:<点路径>` / `count:<pat>` 匹配行数）；失败 → `ok=False`。S-4 定稿：stages 只认 `staging` / `production`（可带 `label`）；`budget.<key>` 按文件顺序、`cap` 省略＝无上限；三组 key 全局唯一，结果键 `config.<key>`；`Config.specs()` 按阶段 → 预算 → 证据顺序给出全部 `CommandSpec`（含 `kind` / `result_key`）。

## 10. 夹具形态（`tests/board/`）

`tests/board/fixtures/<case>/{任务表.md, snapshot.json, expected-simple.txt, expected-complex.txt, expected-why.txt}`；`run_fixtures.py` 对每个 case 跑 `board.py --fixture <dir> --dump --view … --width 150 --height 52 [--why]` 比对（`python3 -B`，零网络，`gh` / `git` 不可用也必须绿）。案例：`trace1-replay`（本仓真实历史 `--record`，`--now 2026-09-02T12:00Z`，三件事）、`simple-t0/t1/t2`、`complex-f1..f4`、`unknown-gh`、`unknown-cmd`、`stage-merged/published/closed`；另有键盘字节流、登记表完整性、结构断言、线程异常后仍刷新、整轮超时单测。

## 11. 体量与禁词

`plugin/` 体量上升须在 CHANGELOG 写明理由（日落条款）；`check_no_lingxi.sh` 对 `plugin/`、`template/` 扫项目名词，对全仓扫本机路径 / 主机名 / 凭据形态——代码注释、夹具、快照文件都不得含。
