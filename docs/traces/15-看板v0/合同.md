- **用户结果一句话**：产品负责人在 tmux 里开一个 window 跑 `/trace-kit:board`，30 秒内说出本 Trace 做到哪、堵在哪、费在哪。本 Trace 自己就是第一个被看的 Trace。

- **完成定义（Delivered）**：#12 六条关卡与 #13 五条关卡全部达成（规则集一条由产品负责人操作，未操作则如实标「需 PM」）；`v0.2.0` tag 指向 main；收口评论含证据等级与未验证清单；产品负责人在 tmux 里看过一次本 Trace。
- 既定条款：交付终点按 `METHOD.md` §3.2 逐项声明——PR 合并、组件存在、CI 通过都不自动升级实际终点。

## 3. 不做清单

- **本 Trace 明确不做**：GitHub Mermaid、GitHub Action 回贴固定评论、Pages / HTML 页面；任何服务器；token 与费用统计；配置 DSL 或 `steps.yaml`；Graph Linter 作为门禁；事件日志真源；看板红了就挡合并；跨 Trace 汇总；Issue / PR 号主键兼容模式；进 `template/` 的 Action 或 CODEOWNERS（等第一个采用项目）；改 `METHOD.md`。
- 既定条款：新发现问题默认只登记不立项——主线灯塔：**不做它，产品负责人能不能在 tmux 里看到本 Trace 的进度？**（`METHOD.md` §6.2）
- 既定条款：疑问句只答不动手；看板的颜色、布局、动效以 #12「设计裁定记录」十二条为准，编排者与子代理不再自行改动。

## 4. 验收标准

- **可观察完成标准**：#12「可观察的完成标准」六条 + #13 五条，逐条见 `验收.md`。
