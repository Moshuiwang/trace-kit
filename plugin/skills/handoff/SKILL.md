# 编排者交接文档

你是即将卸任的编排者。产出一份让下一任**零口头交接**就能接手的文档，落到当前 Trace Issue 的评论（这是六任编排者验证过的最成功协作资产——认真写）。

## 交接前：批次收口序列与复盘评论（`METHOD.md` v25 §五）

顺序固定：**收口评论 → 复盘评论 → 交接评论（本 skill）→ 释放租约**；复盘评论落地才算退场完成。Trace 收口时由末任编排者补全程终值；夜班或例外形态的编排者各写一份。

复盘评论七项（`METHOD.md` §五的六项 + 产品负责人 2026-09-29 点名的套件增补第 7 项），每项都写、没有就写「无」：

1. 做对的（保留）。
2. 做错与可改进（各附修法）。
3. 接缝与陷阱（本机 / 环境事实）。
4. 墙钟按环节归类（有效机器工作 / 等产品负责人 / 等额度与换人 / 返工 / 浪费）与排期对账；附「预估 vs 实际」表（事项 / 预估工作时间 + 机器等待 / 实际 / 偏差原因），新样本回写时间校准表。
5. 用量按模型与通道。
6. 方法候选：每条标归属（方法正文 / trace-kit 程序 / 仓库文档或工作项 / 本机记忆）与出处评论链接。守望者退场前把第 6 项汇总归档到本版修订 Issue（trace-kit 仓库；方法正文与 trace-kit 程序两类归档到那里，公开仓库只写方法层面结论）。
7. 外部路径检查：对第 2 项的主要问题，逐版本查看自上次复盘以来 Claude Code 的 What's new / changelog，再查官方文档与官方博客，记录「问题 / 官方功能或做法（链接 + 版本或日期）/ 能否替代或补强现有规矩 / 采用建议 / 验证方式」，并用 `claude --version` 标出本机尚未包含的版本；查不到写「未找到」，不凭记忆写功能名。结论进下一个 Trace 合同 §6「上次复盘建议采用的官方功能」。

「方法已覆盖、只是执行没照做」的现象只留在复盘，不进方法正文。

## 自动清理（收口序列内、交接评论前）

前提：合同 §2 已勾选「收口自动清理授权」；未勾选则下面第 1 步的对象也一律列表请授权。清理依据只认任务表「资源登记」：只清本 Trace 登记过的对象，未登记的一律不动、写进第 5 节。

1. 按类型判定，满足即清理并逐项回读（`git worktree list`、`git branch -a`、`git ls-remote --heads origin <分支>`、进程表）：worktree 与本地分支 =「已合并 + 无未提交改动 + 无进程占用」；远端分支 =「已合并 + 本 Trace 创建」；临时目录 =「无进程占用 + 内容已转贴或登记为不需保留」；后台进程与等待 =「自己启动 + 目标已结束或已无用」。回读才算清掉——删远端分支的包装命令可能打印「remote ref does not exist」而实际已删，也可能相反。
2. 有风险的不自动清：未合并提交、未提交改动、他人或共享机器上的、需提权、生产机、归属不明——列成表（对象 / 风险 / 建议动作）请产品负责人授权。
3. 自动模式分类器会拦批量删除：被拦时不绕、不拆成多条硬删；生成一份带逐项复核（先核合并 / 未提交 / 占用三条件，不满足即跳过并打印原因）的清理脚本，请产品负责人用一条命令（如 `! bash <脚本>`）执行，执行后编排者回读。
4. 清理结果（已清 + 回读证据 / 待授权 / 保留及理由）回写资源登记表，并在收口评论里给链接。

## 交接评论必含七节

1. **现场快照**：main SHA、当前分支与未合并 PR 清单；若项目有部署面：环境健康态、制品标识、迁移 head。
2. **在途工作**：每个运行中的子代理/后台任务（task id、在做什么、预计何时完、卡点）；**有未提交改动的 worktree 逐个列出路径与归属**；自己挂的等待循环、观察哨与定时提醒逐个列出（没有写「0」），交接前能结束的先结束。
3. **硬期限**：凭据轮换点、外部窗口、承诺过的时点——按紧迫排序，注明错过的后果。
4. **待产品负责人裁定清单**：编号、每项一句话背景 + 可单字回复的选项。
5. **临时资源盘点**：谁建的 worktree/容器/进程还活着、谁负责清、怎么清（谁建谁清纪律）。
6. **常设授权与纪律指针**：本 Trace 合同位置、合并权归属、已登记的常设授权、受控信息红线（受控信息不进公开面）。
7. **一句话接手 prompt**：下一任新会话的第一条输入原文（形如「你是 <Trace #N> 的编排者，读 #N 最新交接评论后从 X 继续」）。不写本评论自己的评论号（发出前取不到，占位符会逼出一条勘误）；要写就发出后从命令输出取号再编辑回填。

## 底线

- 交接前先把自己手里能收口的收口：该 commit 的 commit，该杀的临时进程杀掉，杀不掉的写进第 5 节。
- 顺序不能反：先收口评论、再复盘评论、再本交接评论、最后释放租约；复盘没落地不算退场。
- 未验证的事项如实标「未验证」，不许为了交接好看而标绿。
- 交接评论首行含相关 Step ID，便于看板把这条留痕归属到对应模块（没有 Step ID 时看板只能按时间窗推断）。
- 写完后回读一遍：假设读者对本会话零上下文，七节是否自足。
