## 六条款（源自 `METHOD.md` v16 §6.4，现 v22 §四「派发、审核与验证」；不得删减）

1. **一路做到底**：按自己列的顺序做完再报，不逐步向编排者确认；只有需要产品取舍、扩大范围、或不同意编排者裁定时才停下。
2. **不得派发任何子代理。**
3. **长命令显式传足够长的超时参数**（本仓完整门禁约 __ 分钟），不让命令转入后台再裸等通知。
4. **启动的验证必须等到结束并消化结果后才许收口**，不得「已启动」即停。
5. **报告格式含逐条处理状态**：已改 / 未改 + 原因——不同意编排者的裁定是允许的，但要给证据。
6. 公开可见内容标注与最小披露复核按《协作约定》：本机路径、主机名、凭据、受控信息不进公开面。

## 实测附加条款

- 长命令显式传超时（Bash 工具 `timeout` 毫秒，上限 600000）；预计 >2 分钟的命令一律后台或显式超时，等待用 until 循环。
- **等待只认自己**：until 的判活条件只许 ① 自己启动的进程 PID（`until ! kill -0 <PID>`）、② 自己命令显式写出的产物标记（如 `; echo "EXIT:$?" > <标记文件>`，不猜第三方工具的输出格式）、③ 状态变化；**三种都必须带硬超时**；**禁止按进程名 / 命令行模式等待**（会命中循环自身，方括号写法也会等到别人的进程）。终态集合写成白名单：成功、失败、被拦 / 放弃、超时都能让循环退出；被等的命令中止时一并结束对应等待；上线前先验一次「目标已结束时循环确实退出」；收口前结束自己起的所有等待。
- 独立 worktree、单写入者；不动他人目录。
- 临时文件只放私有 scratchpad 子目录。
- Python 项目：变异实测与测试全程 `python -B` 或逐次清 `__pycache__`；先确认被测模块 `__file__` 在源码树（非 editable 安装假绿）。
- 变异还原与撤销改动禁用 `git checkout -- <文件>` / `git restore` / `git reset --hard` 之类整文件撤销（会连同本卡改动一起冲掉），只用编辑逐处还原。
- 进等待必须上报（等什么、预计多久、到点查什么）。
- 留痕里的评论号 / SHA / 时刻一律由命令输出粘贴、不手写（#843 两任各错一次：5725391087 勘误、S-2-5 评论号误写波及三份文档）。
- 修复包每处改动各自证红（用例或变异），不用一次总跑证明多处（#843 r3 P2）。
- 同批并行卡不得追加同一共享测试支撑文件；各建独立的 `tests/support/fake_<模块>.py` 之类文件（两卡同时追加一个 fake 文件，合并交错 55 例红）。
- 文档里抄源码的字段表由程序实取（如 `dataclasses.fields()`），不手抄（手抄错两处，下游接口冻结返工）。
- 集成 / 端到端卡：正路径用例必须含真实数据形态行，不得为通过而过滤掉（过滤后绕过缺口，靠审核者抓出）；碰运行路径的卡至少一条用例经「调用链」的真实入口走到改动点，直接调内部函数的用例不算接线证据。
- 修复卡（命中才填）：审核者探针已复制到你的 scratchpad `______`，复跑它作为绿证据；复核者会用自己改写版再攻。
- 禁令与已裁定取消项（逐条列出，不依赖中途转达）：______。
- 真实外部写 / 生产命令（命中才填）：本卡不执行，只把完整命令行写进报告，由合同 §2 指定的执行者执行；远端命令整段落脚本文件执行，参数不含 `;`、`|`、`&&` 等 shell 元字符。
- 一次性运维脚本（命中才填）：体量上限 __ 行；只读探针先行；自带清理子命令；到终态预计时长 __。

## 报告格式（≤60 行，直接写在最终回复里）

1. 产出文件清单（相对路径 + 一句话）。
2. 逐条对照「必做项」：已做 / 未做 + 原因。
3. 跑过的验证命令与结果（原样摘要，含失败）。
4. 与卡面裁定不一致之处及证据。
5. 留给编排者的注意事项（跨目录依赖、未验证项、下游接口冻结需要的字段表、自报的取舍与未覆盖项——供审核者定级；本卡新建且仍存在的 worktree / 分支 / 后台进程 / 临时目录清单）。
6. 最后一个 commit SHA。

## 审查派发（审查卡才填；实施卡删除本节）

- 审核对象 = 冻结候选 `<sha>`；只读、不修、不参与实现；候选 SHA 改变后本结论失效（`METHOD.md` §四「派发、审核与验证」）。
- 视角：需求 / 实现 / 测试 / 合并面；从关键测试抽 3–5 个独立复做变异实测（独立 worktree、私有 scratchpad、`python -B`）。
- 固定结构：卡面写死的威胁模型逐项复攻 → 假证据六型 → 独立变异 ≥ N（至少半数与实施者自测不同）→ 「实施者自报取舍请定级」段（实施者报告第 4 / 5 节列出的取舍，审核者独立定 P0 / P1 / P2，不沿用实施者的定级）。
- 输入载荷先核：报告首行写读入的候选 SHA 与字节数 / 文件数；退出码为零、报告非空不算已审。变异验红以日志原文 Ran N（N > 0）为准，环境错误零用例红不计。审核者工作树保留到该批次合并。
- 产出：逐条发现（P0 / P1 / P2 + 证据 + 复现步骤），有无发现都留证；「无法从证据判定」的项标明缺什么证据，不算缺陷。
- 只报影响正确性或既定需求的缺口，其余标可选；审核者天生会报问题，追着每条改会过度工程。
