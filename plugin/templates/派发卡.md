## 六条款（`METHOD.md` §6.4，不得删减）

1. **一路做到底**：按自己列的顺序做完再报，不逐步向编排者确认；只有需要产品取舍、扩大范围、或不同意编排者裁定时才停下。
2. **不得派发任何子代理。**
3. **长命令显式传足够长的超时参数**（本仓完整门禁约 __ 分钟），不让命令转入后台再裸等通知。
4. **启动的验证必须等到结束并消化结果后才许收口**，不得「已启动」即停。
5. **报告格式含逐条处理状态**：已改 / 未改 + 原因——不同意编排者的裁定是允许的，但要给证据。
6. 公开可见内容标注与最小披露复核按《协作约定》：本机路径、主机名、凭据、受控信息不进公开面。

## 实测附加条款

- 长命令显式传超时（Bash 工具 `timeout` 毫秒，上限 600000）；预计 >2 分钟的命令一律后台或显式超时，等待用 until 循环。
- 独立 worktree、单写入者；不动他人目录。
- 临时文件只放私有 scratchpad 子目录。
- Python 项目：变异实测与测试全程 `python -B` 或逐次清 `__pycache__`；先确认被测模块 `__file__` 在源码树（非 editable 安装假绿）。
- 进等待必须上报（等什么、预计多久、到点查什么）。

## 报告格式（≤60 行，直接写在最终回复里）

1. 产出文件清单（相对路径 + 一句话）。
2. 逐条对照「必做项」：已做 / 未做 + 原因。
3. 跑过的验证命令与结果（原样摘要，含失败）。
4. 与卡面裁定不一致之处及证据。
5. 留给编排者的注意事项（跨目录依赖、未验证项）。
6. 最后一个 commit SHA。

## 审查派发（审查卡才填；实施卡删除本节）

- 审核对象 = 冻结候选 `<sha>`；只读、不修、不参与实现；候选 SHA 改变后本结论失效（`METHOD.md` §6.6）。
- 视角：需求 / 实现 / 测试 / 合并面；从关键测试抽 3–5 个独立复做变异实测（独立 worktree、私有 scratchpad、`python -B`）。
- 产出：逐条发现（P0 / P1 / P2 + 证据 + 复现步骤），有无发现都留证；「无法从证据判定」的项标明缺什么证据，不算缺陷。
