# 开工合同：<短名>（Trace [#<issue号>](<Issue 链接>)）

> 用法：开新 `[tracking]` Trace 时逐段填写，落为仓库 `docs/traces/<issue号>-<短名>/合同.md`（三件套之一，PR 合并即批准）；Trace Issue 只留瘦指针与裁定界面。填完删掉本用法段。
> 方法版本：`METHOD.md` v__。合同版本：**v1**。批准依据 = 产品负责人 <日期> 指令（原话要点：「______」）。**本 PR 合并即批准 v1**。
> 一条获批合同 = 编排者长程自治的全部授权依据；未写进合同的授权不存在。
> **合同只认两种来源**：产品负责人裁定（原话 + 时间）与输入 Issue 的可观察完成标准。上一任执行者自设的约束（一次性额度、重型 harness、审核轮次、工具选择）不是合同——继任者按卡面重估，不继承。

- 既定条款：疑问句只答不动手；产品品味类修订夜间只出草案不落地。

## 4. 验收标准

- 可观察完成标准（逐条可勾选；细则见 `验收.md`）：______
- 证据等级要求：关键路径至少 ______；宣称交付前的未验证层级必须列明。
- 既定条款：用户可见断言双通道观测，两条独立通道一致才定论，冲突升产品负责人（`METHOD.md` §4.6）。
- 既定条款：**证据只认仓库 / GitHub 留痕**——审核结论、真实验证结果、失败事件一律当天落对应 Issue 评论或 PR；只存临时目录、会话或交接词的状态视为不存在（`METHOD.md` §6.7）。
- 既定条款：**产品负责人真人验证块**只放两处——实施最前（前置输入 / 裁定，一次给齐）或 Trace 最后（收口验收）；中途不请产品负责人试错；每块先出示就绪自检（前提核对 + 日志回读 + 预判断点），一次只给一条指令。

## 6. 主线声明

- 本 Trace 的主线是：______；任何派发前先问「不做它主线是否受阻」。
- `execution_adapter`：`claude_tmux_named_session`——常驻 tmux session `______` + 每批一个批次代号 window `______`（拉起姿势见 `guardian` skill）；元守护 = ______（规划者或上任编排者转任，只以外部证据判活，不实施、不持合并权，`METHOD.md` §6.8）。
- 单一写入者：当任编排者持主工作树与合并权；实施子代理各用独立 worktree，改完先 commit 再汇报；审核子代理只读固定候选；面向 main 的 PR 串行合并。
- 既定条款：默认攒批进批次分支（子改动只跑快检），批次终点一次完整门禁 + 一次批量审查 + 唯一合并人合并（`METHOD.md` §6.3）；批次收口固定序列（收口评论 → 交接评论 → 继任 window → 接管登记 → 租约转移 → 退场，`METHOD.md` §6.8）。
- 收尾必含：环境清理与残留盘点（临时进程 / 容器 / worktree / 远端分支谁建谁清）、任务表勾选回写、批次收口评论（UTC + 北京双标注 + 预算消耗 + 完整门禁次数 / commit 数 / 子代理人次）。
